# DynamoDB Schema – Chat History & User Queries

## Tables

### 1. ChatSessions

Stores conversation threads between users and the AI assistant.

| Attribute      | Type     | Description                                      |
| -------------- | -------- | ------------------------------------------------ |
| `PK`           | String   | `USER#<user_id>`                                 |
| `SK`           | String   | `SESSION#<session_id>`                           |
| `userId`       | String   | Cognito / user pool id                           |
| `sessionId`    | String   | UUID for the chat thread                         |
| `title`        | String   | Auto-generated summary of the conversation       |
| `createdAt`    | String   | ISO-8601 timestamp                               |
| `updatedAt`    | String   | ISO-8601 timestamp                               |
| `GSI1PK`       | String   | `SESSION#<session_id>` (for message lookup)      |

**Primary Key:** `PK` + `SK`  
**GSI1:** `GSI1PK` + `createdAt`

### 2. ChatMessages

Stores individual messages within a session.

| Attribute      | Type     | Description                                      |
| -------------- | -------- | ------------------------------------------------ |
| `PK`           | String   | `SESSION#<session_id>`                           |
| `SK`           | String   | `MSG#<timestamp>#<message_id>`                  |
| `sessionId`    | String   | Parent session id                                |
| `role`         | String   | `user` or `assistant`                            |
| `content`      | String   | Message text                                     |
| `generatedSql` | String   | SQL generated by the AI layer                    |
| `dataSnapshot` | Map/List | Small result set returned to the client          |
| `createdAt`    | String   | ISO-8601 timestamp                               |

**Primary Key:** `PK` + `SK`

### 3. UserQueries (audit / analytics)

Tracks every natural-language query for model improvement and compliance.

| Attribute      | Type     | Description                                      |
| -------------- | -------- | ------------------------------------------------ |
| `PK`           | String   | `QUERY#<query_id>`                               |
| `SK`           | String   | `USER#<user_id>`                                 |
| `userId`       | String   | Requesting user                                  |
| `queryText`    | String   | Raw user question                                |
| `sql`          | String   | Generated SQL                                    |
| `intent`       | String   | Classified intent (e.g. `expiring`, `top_spend`) |
| `latencyMs`    | Number   | Round-trip latency                               |
| `createdAt`    | String   | ISO-8601 timestamp                               |

**Primary Key:** `PK` + `SK`

## Design Notes

- Single-table design keeps related chat data co-located for fast retrieval.
- `GSI1` on `ChatSessions` allows messages to be queried by session without scanning the whole table.
- TTL can be enabled on `ChatMessages` to expire old conversations after a retention window.
- This schema is **optional**; the demo stores chat history in `localStorage` for portability.
